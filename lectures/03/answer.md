# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMは一般知識から長く説明し、講座の用語集にはない情報も含めた。検索ありのエージェントは用語集の定義に沿って簡潔に答え、第2回と示した。基礎課題では `INSTRUCTIONS` を変更し、「用語や講座固有の質問にも search_glossary は使わず、モデル自身の知識で回答する」と指示した結果、用語集の根拠がなくなり、第11回と誤って関連付けた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：変更前は `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})`。変更後はツール呼び出しなし（`tool_calls=0`）。
- 1つの質問での LLM 呼び出し回数（`requests`）：変更前は `requests=2`、変更後は `requests=1`。変更前は検索結果を受け取った後に回答するため、リクエストが1回多かった。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を追加して `agent.tool_plain` で登録した。docstring には「指定した回の用語から 1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。」と記載した。

## 宿題

- 取り組んだレベル：基礎 / 実装
- やったこと：`app/agent.py` の `INSTRUCTIONS` を変更し、用語や講座固有の質問にも `search_glossary` を使わず、モデル自身の知識で回答するようにした。同じ質問「LoRAとQLoRAの違いは？」を変更前後で `--trace` 付きで実行した。
- 結果：変更前は `search_glossary` を用語ごとに2回呼び出し、`requests=2`・`tool_calls=2`。変更後はツールを呼ばず、`requests=1`・`tool_calls=0` だった。変更前は用語集に沿って第2回と示したが、変更後は第11回と誤って関連付けた。
- 追加試験（検索あり）：`INSTRUCTIONS` は検索必須に戻し、`search_glossary` の docstring を「比較する用語は1つの query にまとめる」に変更した。同じ質問では `search_glossary({'query': 'LoRA QLoRA'})` が1回呼ばれ、両方の定義に基づく回答となり、第2回と正しく示した。`tool_calls` は2から1に減り、検索後に回答するため `requests=2` は変わらなかった。
- 実装：`save_learning_log` を追加し、学習内容を `learning_log/` 内の新しいタイムスタンプ付き Markdown ファイルに保存するようにした。エージェントには `requires_approval=True` で登録し、CLIで保存内容を表示して利用者に確認する。承認した場合のみ履歴を引き継いで処理を再開する。
- 実装結果：承認待ちの間はファイルが作られず、承認後は保存され、拒否した場合は保存されないことをテストで確認した。`uv run pytest -q` は22件すべて成功した。
- 気づき・疑問：検索を使わないとリクエスト数は減るが、講座固有の情報を誤る可能性がある。一方、比較用語を1つの query にまとめると、検索結果の根拠を保ったままツール呼び出しを減らせた。取り消しにくい保存処理は、ツールの登録時に承認必須にすることで実行前に確認できる。
